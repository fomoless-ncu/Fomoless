## 1. 建立 AWS 帳號（root user）

| 項目 | 選擇 | 理由 |
| --- | --- | --- |
| 帳號方案 | **免費方案（Free plan）** | 開發期不會產生帳單，誤開昂貴服務只會消耗抵用金。 |
| 支援方案 | **Basic Support**（免費） | 包含帳號與帳單客服、文件、AWS Health。付費支援月費遠高於本專案的 AWS 用量。 |
| 抵用金 | 註冊 US$100，完成入門任務最多再 US$100 | 主控台 Credits 頁顯示效期 **1 年**。 |

:::warning
**免費方案 6 個月到期**：到期未升級，帳號會暫停，90 天後永久刪除。預計**第 5 個月**或正式上線前升級成付費方案，剩餘抵用金會自動帶到之後的帳單。
:::

:::spoiler 為什麼不用 AWS Organizations
- 加入 Organizations 會讓帳號自動升級成付費方案，開發期失去「不產生帳單」的保護。
- 只有一個帳號，用 IAM 群組就能控管權限。
- 正式上線時若要拆開發、正式兩個帳號，再導入 Organizations 與 SCP。
:::

## 2. 成本防護

### 2-1 成本異常偵測（Cost Anomaly Detection）

啟用 Cost Explorer 後，AWS 自動建立成本異常偵測與預設通知 `Default-Services-Subscription`。預設門檻為 US$100 且超過 40%，對本專案太高，已調整如下：

| 設定 | 預設值 | 調整後 |
| --- | --- | --- |
| 通知頻率 | Daily summaries | Daily summaries |
| 門檻 | US$100 AND 40% | **US$5.00 AND 80%** |
| 收件人 | 帳號信箱 | ccchengchuuu@gmail.com |

本專案預期花費接近 0，任何 US$5 的異常都會超過 80%，因此「且」的條件不會漏報。成本異常偵測與每日摘要信皆免費。

### 2-2 AWS Budgets 預算警示

| 欄位 | 設定 |
| --- | --- |
| Budget name | `FomoLess-Monthly-5USD` |
| Budget type | Cost budget（Customize advanced） |
| Period / Renewal | Monthly / Recurring |
| Budgeted amount | Fixed US$5.00 |
| Scope | All AWS services |

| 警示 | 門檻 | 觸發條件 |
| --- | --- | --- |
| 1 | 80% | Actual（實際花費） |
| 2 | 100% | Forecasted（預測花費） |

:::spoiler 兩種成本防護的差別
- **Budgets**：總花費快超過預算時通知，預測警示會在 AWS 預估本月將超支時提前寄信。
- **成本異常偵測**：某個服務花費突然暴增時通知，例如忘了關 NAT Gateway。
- 兩者互補，都設最保險。
:::

## 3. 啟用台北區域

1. 以 gl-pupu 登入，右上角帳號名稱 → **Account**。
2. 找到 **AWS Regions**，勾選 Asia Pacific (Taipei) → **Enable**。
3. 狀態顯示 **Enabled** 即完成。

必須先啟用台北區域，否則 Developers 群組的「只能在 ap-east-2 操作」政策會讓開發者在任何區域都無法建立資源。

:::spoiler 為什麼要擋台北以外的區域
1. **忘記關的資源會躲在別的區域**：主控台一次只顯示一個區域，在其他區域建的資源不容易被發現，卻持續計費。
2. **同一系統的服務要在同一區域**：跨區域呼叫較慢，還會產生跨區域資料傳輸費。
3. **降低帳號被盜用的損失**：攻擊者常在平常不看的區域開機器挖礦。
4. **學生資料留在台灣**：之後撰寫隱私權政策較單純。
5. **延遲最低**：使用者都在台灣。

例外：IAM、CloudFront、帳單、預算等全域服務不受限制。之後若要替 CloudFront 綁自訂網域（ACM 憑證需在 us-east-1），或需要台北尚未提供的服務，由管理員操作或再調整政策。

### 使用者

| `test-dev` | Developers | 驗證開發者權限，測試完成後刪除。 |

### 角色

| 角色 | 信任對象 | 附加政策 | 用途 |
| --- | --- | --- | --- |
| `FomoLess-Lambda-DevRole` | Lambda | `AWSLambdaBasicExecutionRole` | 開發期 Lambda 共用的執行角色，可寫入 CloudWatch 日誌。 |

### 帳單權限

已用 root user 開啟 **IAM user and role access to Billing information**（Account → Edit → Activate IAM Access）。

- Admins（`AdministratorAccess`）可以查看帳單。
- Developers 沒有帳單權限，仍然看不到帳單，符合設計。

:::spoiler 建立 IAM 使用者的步驟
1. IAM → **Users** → **Create user**，名稱用英文。
2. 勾選 **Provide user access to the AWS Management Console** → **I want to create an IAM user**。
3. 密碼選 **Autogenerated password**，勾選 **Users must create a new password at next sign-in**。
4. **Add user to group** → 選擇群組 → **Create user**。
5. 登入網址與密碼分兩個管道交給組員。
6. 組員首次登入：改密碼 → 右上角名稱 → **Security credentials** → **Assign MFA device**。
:::

## 5. 權限政策設定

### Developers 群組附加的政策

| 政策 | 類型 | 用途 |
| --- | --- | --- |
| `FomoLess-DenyCostly` | 自訂 | 限定台北區域、禁止昂貴服務 |
| `FomoLess-SelfManageMFA` | 自訂 | 讓使用者自己綁定 MFA |
| `AWSLambda_FullAccess` | AWS 內建 | 管理 Lambda、查看日誌、選用既有執行角色 |
| `AmazonDynamoDBFullAccess` | AWS 內建 | 資料庫 |
| `AmazonS3FullAccess` | AWS 內建 | 海報與網頁檔案 |
| `AmazonSQSFullAccess` | AWS 內建 | 推播佇列 |
| `AmazonAPIGatewayAdministrator` | AWS 內建 | API Gateway |
| `AmazonEventBridgeSchedulerFullAccess` | AWS 內建 | 排程 |
| `IAMUserChangePassword` | AWS 內建 | 自行修改密碼 |

一個群組最多附加 10 個政策，目前用了 9 個。

:::spoiler FomoLess-DenyCostly（禁止清單，v1）
Description：`Deny actions outside ap-east-2 and block costly services (EC2, NAT Gateway, RDS, etc.) for FomoLess developers`

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "OnlyOurRegion",
      "Effect": "Deny",
      "NotAction": ["iam:*", "sts:*", "cloudfront:*", "budgets:*", "ce:*", "support:*"],
      "Resource": "*",
      "Condition": { "StringNotEquals": { "aws:RequestedRegion": "ap-east-2" } }
    },
    {
      "Sid": "NoCostlyServices",
      "Effect": "Deny",
      "Action": ["ec2:RunInstances", "ec2:CreateNatGateway", "rds:*", "sagemaker:*",
                 "redshift:*", "es:*", "elasticache:*", "bedrock:*"],
      "Resource": "*"
    }
  ]
}
```

- **OnlyOurRegion**：除了 IAM、CloudFront、帳單等全域服務，所有操作只能在 ap-east-2 執行。
- **NoCostlyServices**：禁止按小時計費、最容易造成意外帳單的服務。Deny 一律優先於 Allow。
:::

:::spoiler FomoLess-DenyCostly（v2：讓區域選單正常顯示）
與 v1 的差異：`NotAction` 加入 `"account:*"`，並新增 `AllowListRegions`，只開放**查看**區域清單與狀態。Developers 仍無法啟用或停用區域。

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "OnlyOurRegion",
      "Effect": "Deny",
      "NotAction": ["iam:*", "sts:*", "cloudfront:*", "budgets:*", "ce:*", "support:*", "account:*"],
      "Resource": "*",
      "Condition": { "StringNotEquals": { "aws:RequestedRegion": "ap-east-2" } }
    },
    {
      "Sid": "NoCostlyServices",
      "Effect": "Deny",
      "Action": ["ec2:RunInstances", "ec2:CreateNatGateway", "rds:*", "sagemaker:*",
                 "redshift:*", "es:*", "elasticache:*", "bedrock:*"],
      "Resource": "*"
    },
    {
      "Sid": "AllowListRegions",
      "Effect": "Allow",
      "Action": ["account:ListRegions", "account:GetRegionOptStatus"],
      "Resource": "*"
    }
  ]
}
```

套用方式：IAM → Policies → `FomoLess-DenyCostly` → **Edit** → JSON 全部取代 → **Next** → **Save changes**。AWS 會保留舊版本，可在 **Policy versions** 切回。
:::

:::spoiler FomoLess-SelfManageMFA（自行設定 MFA）
```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["iam:CreateVirtualMFADevice", "iam:EnableMFADevice", "iam:ResyncMFADevice",
                 "iam:ListMFADevices", "iam:GetUser"],
      "Resource": ["arn:aws:iam::*:user/${aws:username}", "arn:aws:iam::*:mfa/*"]
    },
    {
      "Effect": "Allow",
      "Action": "iam:ListVirtualMFADevices",
      "Resource": "*"
    }
  ]
}
```

`${aws:username}` 讓每個人只能管理自己的 MFA，無法修改別人的。
:::

## 7. 問題排除：Lambda 無法建立執行角色

:::danger
**錯誤訊息**

User: arn:aws:iam::6974••••5832:user/test-dev is not authorized to perform: iam:CreateRole on resource: arn:aws:iam::6974••••5832:role/service-role/test-role-bv16akdf because no identity-based policy allows the iam:CreateRole action
:::

**原因**

Lambda 主控台建立函式時，預設會自動建立一個執行角色，但 Developers 群組沒有 `iam:CreateRole` 權限。

這是刻意的設計：能自行建立角色的人，可以替自己建一個權限更大的角色來繞過禁止清單，所以**不開放**開發者建立 IAM 角色。

**解法**

1. 以 gl-pupu（管理員）到 IAM → **Roles** → **Create role**。
2. Trusted entity 選 **AWS service**，Use case 選 **Lambda**。
3. 附加 `AWSLambdaBasicExecutionRole`，命名為 `FomoLess-Lambda-DevRole`。
4. 以 test-dev 建立函式時，展開 **Additional settings** → Execution role 選 **Use an existing role** → 選擇 `FomoLess-Lambda-DevRole`。
5. 開發者能選用既有角色，是因為 `AWSLambda_FullAccess` 已包含把角色交給 Lambda 的 `iam:PassRole` 權限。

:::success
**結果：成功建立函式 test**

`arn:aws:lambda:ap-east-2:6974••••5832:function:test`
:::

:::spoiler 建立函式時的其他設定
- **Durable execution**、**EC2 capacity provider** 保持關閉。後者會改用 EC2 按機器計費，不符合按次計費的設計。
- 測試時選了 Node.js 24.x；正式開發依規劃使用 Python。
- 之後函式需要 DynamoDB、S3、SQS 權限時，由管理員加到角色上；正式環境的角色由 SAM 部署時建立，每個函式只給需要的權限。

## 8. 帳號安全：MFA

| 帳號 | MFA | 狀態 |
| --- | --- | --- |
| root user | Authenticator app | ✅ 完成 |
| gl-pupu | 待綁定 | ⏳ 待辦 |

:::spoiler 綁定 MFA 的步驟
1. 右上角帳號名稱 → **Security credentials**。
2. **Multi-factor authentication (MFA)** → **Assign MFA device**。
3. Device name 例如 `root-pupu-phone`，類型選 **Authenticator app** → **Next**。
4. 用 Google Authenticator、Microsoft Authenticator 或 Authy 掃描 QR code。
5. 輸入連續兩組驗證碼 → **Add MFA**。

root user 最多可綁 8 個 MFA 裝置，建議再加一個備用裝置（另一支手機或 Passkey），避免手機遺失無法登入。
